A slow-walk audit, not a build sprint. Branch `sweep-2026-09-06`, nothing merged.

## 0 · The spec, as ruled on 2026-09-06

The founder's ruling this session sharpens `helpers/entitlement.py`'s docstring in
two places that turn out to matter a great deal. Written out in full, because
three of the findings below are only findings *because* of the refinement:

1. **FREE** — everything derivable from a **box score**, **excluding implied
   possessions**. Final scores, records, W-L, per-player counting lines, shooting
   percentages, rankings built from results. The 0.44-FTA possession estimate and
   anything computed per-possession is **not** Free even though its inputs are.
2. **PAID** — full tracked depth on **your own team**, and on **any tracked data
   you created yourself**, whoever it is about.
3. **CO-OP** — required the moment a surface shows tracked data the coach did not
   enter themselves. This is the multi-team rule, restated by provenance rather
   than by team: *"if you can see data a coach hasn't completely inputted
   themselves, they must have co-op on."*
4. **PAST SEASONS** — an open archive. Unchanged.

Two of these are new relative to what the code implements:

* **The possession carve-out is already honoured at player level and nowhere
  else.** `player_ratings.EVENT_DERIVED_STATS` puts `PPP` and `TOV%` in the Paid
  set with the exact comment *"possession-derived rates … Paid per the owner
  possession carve-out, even though their box inputs are Free."* There is no
  team-level or league-level equivalent of that list.
* **Provenance never enters the read filter.** `games.tracked_by` records who
  logged a game and is read by exactly one function — `recompute_game_pool` —
  which uses it to decide what to *share*. No gate uses it to decide what its
  author may *read*. §4.1 measures what that costs.

### Why: the archive bypass has no offseason regime

```
active_label        = 2026-2027
default_read_season = 2025-2026
_is_past_season('2025-2026') = True
```

`games`: 13,362 rows under `2025-2026`, **1** under `Current` (unplayed,
2026-12-08). Every season-scoped read gate — `visible_tracked_game_ids`,
`visible_untracked_boxed_game_ids`, `team_visible_tracked_ids`, `tracked_gate` —
starts with

```python
if _is_past_season(season):
    return None          # past = open archive, full depth
```

and `None` means unrestricted. The rule was written for *"last year's roster has
turned over, there is no edge left to protect"*, and it is right. But it was
written assuming a live season exists alongside the archive. **Between a rollover
and the first game of the new year, "the archive" is 100% of the product**, and
that gap is currently four months wide — which is precisely the window (October)
the polish month is aimed at.

This is not a code bug. It is a rule with an unhandled regime, and it needs a
founder ruling before any of the leak fixes below matter, because right now they
all sit behind a bypass that is switched on for everything.

**Three ways to close it, in ascending cost:**

| option | what it does | cost | what it breaks |
|---|---|---|---|
| **A · Rolling window** | archive = seasons that ended **more than N months ago**; the season just played stays gated until the new one starts | one predicate in `_is_past_season`, plus a constant | nothing; today it would re-gate 2025-2026 until ~Nov 2026 |
| **B · Gate on "is there a live season yet"** | archive opens only once the active season has ≥1 finished game | one query, cacheable | the archive is shut for the whole offseason — the funnel argument goes with it |
| **C · Depth-tiered archive** | past seasons open at **box level** to everyone (the funnel), tracked depth still Paid | touches every bypass site | most work, best product |

A is the cheap correct answer and B is a subset of it. C is what the product
probably wants eventually and is a real project, not a polish item.
**Recommend A**, with the window expressed as "the previous season opens when the
new one tips off, or on 1 December, whichever comes first" — a rule a coach can
read on a pricing page.

### And it is inconsistent in both directions at once

Three page-level paid checks do **not** honour the archive rule that
`entitlement.py` honours everywhere:

| site | behaviour on a past season | correct per the rule |
|---|---|---|
| `pages/8_Officials.py:219` | hard `st.stop()` for Free | open |
| `pages/14_Hall_of_Fame.py:504` | tracked block hidden for Free | open |
| `pages/6_Team_Dashboard.py:6038` | Projection hidden for Free | open |
| `pages/9_War_Room.py:256` | *bypasses* — `if _is_cur_season and not has_paid_plan` | ✅ the pattern to copy |

So today Free gets the War Room, the Insights deck and the whole Players page for
free, and is locked out of the Officiating Lab. Whatever the ruling on §1, these
four should agree with each other, and War Room already shows the shape.

## 2 · LEAKS — a persona seeing depth it should not

### 2.1 · `season_wpa` is outside the read filter entirely — **live**

`helpers/wpa.py:422` `season_wpa(gender, mode, opp_adjust, season)` **has no
`game_ids` parameter.** It builds its own pool:

```sql
SELECT g.id FROM games g JOIN teams t ON t.id=g.team1_id
WHERE g.tracked=1 AND g.season=? AND t.gender=?
```

Every consumer therefore gets the whole gender-season tracked pool, whatever the
viewer is entitled to. On this book that is **43 tracked games where the pool is
11** — so a Paid League-wide coach's Def WPA numbers are computed over 32 games
belonging to teams that chose Solo and never shared.

Five consumers, in descending severity:

| consumer | surface | severity |
|---|---|---|
| `helpers/player_edge.py:72` | Players → Lab → **Def WPA leaderboard** | **names players from non-pooled teams** |
| `helpers/dashboard/player_card.py:347-348` | player card impact block | percentile context from an unentitled pool |
| `helpers/dashboard/insights_tab.py:328` | Insights → Who's helping | same |
| `pages/6_Team_Dashboard.py:5635` | Charts → WPA | filtered to own roster after the fact |
| `helpers/reports.py:276-277` | PDF report | **and** it passes no season at all — see §5.2 |

**Plan.** Add `game_ids=None` to `season_wpa`, defaulting to the current query;
thread it from all five consumers. The engine already accepts a list internally
(`S.fetch_events(game_ids)`, `_fetch_floor(game_ids)`), so this is a signature
change and five call sites, not a rewrite. One session. **Do the leaderboard
first** — it is the only one that puts a name on screen.

### 2.2 · The empty read-filter widens to the whole league — **latent, one live**

`visible_tracked_game_ids` returns three things and only two are the same shape:
`None` = unrestricted, `{1,2,3}` = these games, `set()` = **nothing**. The third
is the trap.

`stats._game_filter` already learned this and now branches on `is None` — an
empty collection there means `AND 0=1`. Probed against the live book, every
engine honours it:

```
stats.fetch_events                 none=7670   empty=0
stats.player_game_boxes            none= 285   empty=0
stats.located_shots                none=3798   empty=0
player_ratings.player_stat_table   none= 242   empty=0
officials.official_overview        none=  66   empty=0
playtypes.player_role_splits       none= 108   empty=0
fouls.player_foul_ft               none= 233   empty=0
player_edge.edge_boards            none=   8   empty=8   <-- WIDENS
```

**The engine layer is fixed. The caller layer is not.** An AST scan of `pages/`
and `helpers/` finds **35 sites** that convert the empty case into the
unrestricted case one line before the engine's own guard can see it:

```python
game_ids=(set(gids) if gids else None)     # set() -> None -> everything
```

Of the 35, most are safe *by caller* — `pages/7_Players.py` guards explicitly at
`:425-446` with a comment that names this exact failure, and the four Team
Dashboard sites carry docstrings saying "only reached when has_tracked, so vis is
never empty". Four are **not** guarded:

| site | reachable by | consequence |
|---|---|---|
| `helpers/player_edge.py:51` | anyone — it is inside the **engine** | whole-league edge boards |
| `helpers/dashboard/analyze.py:60` + the `if not table` guard at `:107` | Paid League-wide, empty pool | whole-league tracked player table; the guard tests the wrong thing — an empty filter returns a **full** table, so `_paid` never flips to False |
| `pages/8_Officials.py:238` → `:146/:155/:162/:179` | Paid Solo, current season, no own tracked games | every tracked game's officials data |
| `pages/9_War_Room.py:779` | same | ditto — and its sibling at `:739` is written correctly, so this one is a slip, not a design |

Plus a cache-key collision of the same shape: `helpers/player_ratings.py:1232`
builds `sig = tuple(sorted(game_ids)) if game_ids else None`, so an empty scope
lands on the **same memo key** as the admin's unrestricted call. Whoever runs
first wins for both.

**Receipt.** `tracker/test_read_filter_empty_scope.py` is written and **fails on
`main` today** — three tests: the AST scan (35 hits listed), `edge_boards` with an
empty scope returning populated boards, and the RAPM memo sharing one key across
two different scopes. It is on the branch, unmerged, and is the only file this
session has added to the repo.

**Plan.** The fix at every one of the 35 is the same two words — `is not None` —
and at the four unguarded sites it also needs the surface to render its empty
state instead of a table. Where the caller cannot produce an empty set the change
is a no-op, so converting all 35 costs nothing and turns a comment somebody has
to remember into a mechanical rule the test enforces. **One session, low risk.**

### 2.3 · `visible_tracked_game_ids` does not check the plan

Its own docstring says *"a Free viewer gets an empty set (depth is gated
upstream)"*. It does not check `has_paid_plan` at all. Measured on the
live-season book, a **Free** League-wide coach gets **29 game ids** (own 24 ∪
pooled 11, deduped).

Latent — every current caller happens to gate upstream — but it is the function
whose entire job is to be the read filter's teeth, and it is the one place a
future caller will trust without checking. **Plan:** make the code match its
docstring, and add the assertion to `test_entitlement.py`. Half a session.

## 3 · FALSE DENIALS — a persona blocked from something the spec says is theirs

### 3.1 · A coach cannot read tracked data they entered themselves — **live, big**

The spec says Paid covers *own creation*. `_own_teams` is team membership;
`tracked_by` is provenance; **no gate joins them**.

Measured on the live book:

```
tracked games total                 43
own-TEAM games (team 1)             24
games this coach LOGGED             28
logged but NOT their own team       19   [86,123,128,129,133,178,179,186,214,
                                          225,229,13947,13957,14107,14123,
                                          15331,15340,15344,15349]
  ...and not pooled either          14
```

**14 of 43 tracked games in the book — 33% — were typed in by this coach and are
invisible to them as a Paid Solo coach.** Eight of the 14 are ADAIR Boys games:
the same person tracks the boys team, is not rostered on it, and so cannot read
their own work. Turning co-op on is currently the only way to get it back, which
inverts the co-op pitch — they are being asked to share in order to read
something nobody else contributed.

**Plan.** `visible_tracked_game_ids` and `team_visible_tracked_ids` gain an
own-creation term:

```sql
OR tracked_by = :viewer_email
```

Three things to decide first, and they are product calls, not engineering ones:

1. **Does own-creation extend to the game VIEW as well as aggregates?**
   Recommend yes — `can_see_game_tracked` should return True for a game you
   logged, same as for a game your team played.
2. **Does it survive the coach leaving the program?** `tracked_by` is an email,
   not a role. Recommend yes, and say so — it is their work.
3. **Do the 15 games with an empty `tracked_by` (the old desktop path) get
   attributed to anyone?** Recommend no, and leave them to the team rule.

Then `test_entitlement.py` gains the persona: paid-solo, logged a game about two
other teams, must see it. **One session** once the three rulings land.

### 3.2 · The box score is not Free — **live, and it is the funnel**

`entitlement.py`'s first sentence is *"Box score + final results are Free and
visible to everyone, always."* The app does not do this.

`helpers/box_score.py:render_box_score` is the only box-score view in the app
(three callers: Schedule, Rankings → Tracked, TD → Schedule). It renders the
scoreboard hero, then at `:362`:

```python
if SEAS.is_current(g["season"]) and not ENT.can_see_game_tracked(...):
    st.info(<one of the four lock strings>)
    return
```

Everything below that `return` — including the actual box score tables at
`:473`, `:493`, `:524` — is behind the gate. A Free coach on a current-season
tracked game sees a scoreboard and a padlock. There is no box-only branch.

Worse, the view only exists for **tracked** games at all (`tracked_games = [g for
g in ... if g["tracked"]]` at both `pages/4_Schedule.py:356` and
`helpers/dashboard/sched.py:270`), so a manually entered box has no viewer here
either — that lives in `helpers/manual_box.py`, a different surface with
different chrome.

This is the single biggest product finding of the sweep. The box score of a game
a coach just watched is the most shareable artefact the app produces, and it is
the natural top of the funnel. **It is currently the paywall.**

**Plan — a real layout, not a flag flip.** Split `render_box_score` into two
stages rather than one gated function:

```
render_box_score(game_id)
├── hero          scoreboard, date, venue, FINAL           always
├── BOX  (free)   per-player counting lines, team totals,   always
│                 shooting %, quarter scores, four-factor
│                 SHOOTING terms only (eFG, FT%, 3PAr)
│                 — NO possessions, NO ORtg/DRtg/Pace/PPP
│                 — NO SMOE/xPPS/ShotRating (shot-quality is tap-captured)
└── DEPTH (gated) everything currently below :362 —
                  possession panel, WP curve, shot chart,
                  lineups, play types, defense, SMOE
```

The split point is already sketched in the code: `EVENT_DERIVED_STATS` is the
player-level version of exactly this list. The team-level version does not exist
yet and is the actual work — call it `TEAM_EVENT_DERIVED` and put it next to its
sibling so the two cannot drift.

Note the possession carve-out bites here: `box_score.py:272` computes
`h_poss, a_poss = S.estimate_possessions(...)` and renders "Possessions" and
points-per-100 at `:517-520`. Those stay **above** the paywall line under the old
reading of "box-derivable" and **below** it under the ruling in §0. They are
currently below the gate anyway, so no change — but the constant needs to say so
out loud, because the next person to move that table will get it wrong.

**Effort:** one session for the split, plus one for the `TEAM_EVENT_DERIVED`
constant and its test. **Value:** this is the demo. Do it first.

### 3.3 · `can_see_team_tracked` / `can_see_game_tracked` have no archive bypass

The docstring names four functions the bypass covers and two it deliberately does
not. These two are in **neither list**. They are read gates fronting views, they
take no `season` argument, and so they stay closed on an open archive.

The result is one screen contradicting itself. On Rankings → Team:

* `:1161` `_see_trk = ENT.can_see_team_tracked(...)` → **False** for Free → the
  header card drops the tracked rank and the engine zone;
* `:1405` `ENT.tracked_gate(..., season=season_pick)` → **True** (archive) → the
  full tracked deep dive renders immediately below it.

Same shape at `helpers/dashboard/overview.py:46`, `helpers/dashboard/sched.py:148`,
`pages/9_War_Room.py:649`, and `pages/5_Rankings.py:3560` — where Compare shows a
literal *"🔒 The tracked four-factor & efficiency compare is **Paid**"* over data
the archive rule says is free.

**Plan.** Give both functions the `season=SEAS_DEFAULT` parameter and the same
`_is_past_season` bypass the other four have, then thread `season_pick` from the
six call sites. Update the docstring's two lists so every gate is named in one or
the other — the reason this slipped is that the docstring enumerates and the
functions were added after. **Half a session.** Do it *after* the §1 ruling, since
the ruling may narrow what "past" means.

### 3.4 · The free-demo game is empty in the offseason

### Method, so any number here can be re-run

```
snapshot   sqlite3.connect(live).backup(sqlite3.connect(copy))   # copy named analytics.db
book A     APP5_DATA_DIR=<copy>                                   # as-is; default season is PAST
book B     UPDATE {games,players,rating_snapshots,schedule,team_class_history}
             SET season='Current' WHERE season='2025-2026'        # after deleting the 1 Current game
persona    import helpers.auth as AUTH; AUTH._LOCAL_IDENTITY = <dict>
```

The persona line is the whole trick, and it is worth stating why the obvious
approach fails: the AppTest harness chdir()s into a secrets-free directory, so
`auth.auth_enabled()` is False and `require_login()` short-circuits — but it
**writes** `_LOCAL_IDENTITY` into `st.session_state['auth_user']` on the way
through and returns it. Seeding `session_state` directly is overwritten by the
first line of every page. Rebinding the module global is seen by both
`require_login()` and `current_user()`, and the dict shape is exactly what a real
OIDC login assembles (`email / role / plan / paid_until / team_id / team_ids /
shares_pool / pool_banned`). One process per persona, so a warm cache is never
shared across two identities — a cross-persona cache hit would be a leak served
invisibly.
